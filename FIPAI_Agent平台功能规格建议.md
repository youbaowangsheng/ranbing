# FIPAI Agent平台 — 功能规格建议

> 文档目标：为FIPAI Agent平台定义完整的功能模块，让业务人员能独立构建解决具体问题的AI Agent
>
> 版本：v1.0 | 日期：2026-05-02 | 状态：待评审

---

## 一、现状问题

当前FIPAI Agent平台缺少面向业务人员的「可视化构建能力」，导致：

1. **客户依赖技术团队**：每次新建Agent都需要写代码、配置LLM、对接工具
2. **交付成本高**：一个场景需要一个Agent，技术团队成为瓶颈
3. **平台价值不闭环**：三通道架构已建立，但缺少配套的「配置工具」让客户自主使用
4. **文档缺失**：没有操作手册，客户无从下手

---

## 二、目标

让一个**没有AI背景的业务人员**，能在平台上**自己拼出一个能解决实际问题的Agent**，整个过程不超过2小时。

## 四、功能模块规格

### 模块1：Agent创建向导

**目标：** 用户能快速从0到1创建一个可用的Agent

#### 1.1 Agent基本信息

| 字段 | 类型 | 说明 | 必填 |
|------|------|------|------|
| 名称 | 文本 | 如"供需分析助手"，将展示在App里 | 是 |
| 描述 | 文本 | 一句话说明Agent干什么，供其他用户理解 | 是 |
| 图标 | 图片上传 | 可选，不上传则用默认图标 | 否 |

#### 1.2 Agent类型选择

提供3个可视化卡片，用户根据场景描述选择：

```
┌──────────────────┐  ┌──────────────────┐  ┌──────────────────┐
│   ⚡ 快捷问答    │  │   🔧 技能执行    │  │   🎯 多步编排   │
│                  │  │                  │  │                  │
│ 简单查询、短消息  │  │ 单步操作、单一工具│  │ 复杂任务、多工具  │
│ 处理，毫秒响应    │  │ 调用，适合自动    │  │ 组合，需要规划   │
│                  │  │ 化业务流程       │  │ 和判断           │
│                  │  │                  │  │                  │
│ 例：查信息、解读  │  │ 例：自动发消息、  │  │ 例：供需匹配、    │
│ Profile、分析文字 │  │ 写入数据、发送    │  │ 信号监听、多方   │
│                  │  │ 通知            │  │ 协调            │
└──────────────────┘  └──────────────────┘  └──────────────────┘
```

**注意：** 不要向用户暴露"Channel 1/2/3"这样的内部命名，统一用业务语言。

#### 1.3 LLM配置

| 配置项 | 类型 | 说明 | 默认值 |
|--------|------|------|--------|
| 模型 | 下拉选择 | DeepSeek V3 / GPT-4o Mini / Claude Haiku 等 | DeepSeek V3 |
| 温度 | 滑动条 | 0（精确）— 1（创意） | 0.3 |
| 最大输入Token | 数字 | 单次最大输入 | 4000 |
| 最大输出Token | 数字 | 单次最大输出 | 1000 |

#### 1.4 附加选项

| 配置项 | 说明 |
|--------|------|
| 开启缓存 | 相同输入直接返回缓存结果，节省Token |
| 超时时间 | 超过N秒未返回则判定失败 |
| 失败重试次数 | 0-3次，默认1次 |

### 模块3：技能（Skill）市场

**目标：** 用户能像搭积木一样组合能力，不需要自己写代码

#### 3.1 技能分类

```
📂 搜索类
   ├── 向量检索（输入一段话 → 找最相似的N条记录）
   ├── 数据库查询（输入条件 → 返回记录列表）
   ├── 关键词匹配
   └── 全文检索

📂 文本处理类
   ├── 文字分析（提取标签/意图/实体）
   ├── 文字生成（生成摘要/话术/文案）
   ├── 文字改写（改写风格/长度）
   └── 文字翻译

📂 匹配类
   ├── 供需匹配（用户供需 ↔ 校友供需）
   ├── 人脉推荐（基于Profile ↔ 标签）
   ├── 专家发现（问题主题 → 相关领域专家）
   └── 相似用户发现

📂 推送类
   ├── App通知推送（极光/友盟/自建）
   ├── 邮件发送
   └── 站内消息

📂 数据操作类
   ├── 写入数据库（单条）
   ├── 批量写入数据库
   ├── 更新记录
   ├── 删除记录
   └── 条件筛选
```

#### 3.3 技能编排

技能可以链式组合，前一个技能的输出作为后一个的输入：

```
技能A的输出 {matches[]}  →  技能B的输入
                                    ↓
                             筛选高匹配度   →   技能C的输入
                                                       ↓
                                                生成推送内容
```

#### 4.2 预置工作流模板

平台预置以下模板，用户基于模板修改：

```
模板1：【供需分析+匹配推送】
开始 → AI分析文字 → 提取标签 → 供需匹配 → 生成推荐理由 → 推送通知 → 结束

模板2：【社群信号监听】
定时触发 → 拉取消息 → 信号分类 → 专家匹配 → 生成信号 → 推送 → 结束

模板3：【AI牵线】
用户发起 → 生成话术 → 确认发送 → 通知对方 → 接收响应 → 交换联系方式 → 结束

模板4：【新用户欢迎】
事件触发(新用户注册) → 获取用户Profile → 生成欢迎语 → 发送欢迎消息 → 结束

模板5：【每日机会摘要】
定时触发(每天早9点) → 查询当日新供需 → 匹配目标用户 → 生成摘要 → 推送 → 结束
```

#### 4.3 判断节点

支持条件分支：

```
                    ┌─ tags数量 > 0 ─→ 继续匹配流程
用户输入 ─→ 分析 ─┤
                    └─ tags数量 = 0 ─→ 提示用户完善信息
```
